# 游戏碰撞系统核心扩展功能解析
以下从功能定义、核心逻辑、应用场景三方面，简要解析碰撞系统的5个关键扩展方向：


## 1. 矩形碰撞检测（含矩形-矩形、矩形-圆）
### 功能定义
补充圆形碰撞之外的形状检测能力，适配游戏中矩形物体（如墙壁、箱子）与矩形/圆形物体（如玩家、子弹）的交互场景。
### 核心逻辑
- **矩形-矩形碰撞**：采用“轴对齐包围盒（AABB）”算法，判断两个矩形在X轴、Y轴的投影是否完全重叠。  
  公式：若 `矩形A左 < 矩形B右 && 矩形A右 > 矩形B左 && 矩形A上 < 矩形B下 && 矩形A下 > 矩形B上`，则判定碰撞（需先获取矩形的世界坐标+宽高，计算边界）。
- **矩形-圆碰撞**：先找到“矩形上离圆心最近的点”，再判断该点与圆心的距离是否小于圆的半径。  
  步骤：1. 计算圆心在矩形边界内的“投影点”（若圆心在矩形内，投影点即圆心；若在外部，投影点取矩形最近的边/角）；2. 计算投影点与圆心的距离，与圆半径比较，小于则碰撞。
### 应用场景
墙壁（矩形）与玩家（圆/矩形）的阻挡、箱子（矩形）与子弹（圆）的碰撞判定。


## 2. 碰撞回调
### 功能定义
将“碰撞检测”与“碰撞后的逻辑”解耦，当检测到碰撞时，自动触发预设的函数（回调），避免硬编码耦合。
### 核心逻辑
- 在`Collider`类中添加“回调函数指针/接口”（如`onCollisionEnter`、`onCollisionExit`），允许外部为碰撞器绑定自定义逻辑。
- 检测到碰撞时（如`isColliding`返回`true`），判断是否为“新碰撞”（避免重复触发），若满足则调用双方碰撞器的回调函数，并传入碰撞对象信息（如碰撞方`Collider`、碰撞位置）。
### 应用场景
玩家触碰道具时触发“道具拾取”回调、敌人碰撞玩家时触发“玩家掉血”回调。


## 3. 碰撞分组
### 功能定义
通过“分组标签”控制碰撞检测的范围，避免无关对象的碰撞计算（如“敌人”不与“敌人”碰撞、“道具”只与“玩家”碰撞），减少无效检测并明确交互规则。
### 核心逻辑
- 为每个`Collider`分配“碰撞组ID”（如`Group::Player`、`Group::Enemy`、`Group::Prop`），并维护“碰撞矩阵”（二维数组），定义“哪些组之间需要检测碰撞”（如矩阵中`Player-Enemy`为`true`，`Enemy-Enemy`为`false`）。
- 碰撞检测前先校验双方的碰撞组，若矩阵中该组合为`false`，直接跳过`isColliding`计算，仅对允许碰撞的组执行检测。
### 应用场景
区分“友方/敌方”碰撞（友方不互撞）、“装饰物体”（如树木）不与任何对象碰撞（分组设为`Ignore`）。


## 4. 碰撞响应
### 功能定义
碰撞后模拟真实物理效果，让物体产生“动态反馈”，而非仅触发逻辑，提升游戏真实感。
### 核心逻辑
- 基于“物理参数”（如物体质量、摩擦系数、恢复系数）计算碰撞后的运动状态（速度、方向）。  
  示例：  
  - **弹跳**：碰撞时反转物体在“碰撞法线方向”的速度分量，并乘以“恢复系数”（如恢复系数0.8表示弹跳高度衰减20%）；  
  - **滑动**：若碰撞面有摩擦，沿碰撞面切线方向的速度乘以“摩擦系数”（如摩擦系数0.5表示切线速度减半）；  
  - **推动**：根据双方质量分配动量，质量小的物体被质量大的物体推动（如玩家推箱子，箱子质量大则推动速度慢）。
### 应用场景
小球撞击地面后的弹跳、玩家撞到墙壁后的滑动、箱子被玩家推动的位移。


## 5. 空间分区（以四叉树为例）
### 功能定义
解决“大量物体同时检测碰撞”的性能问题（如1000个敌人同时检测，原逻辑需计算`1000*999/2=499500`次），通过“划分空间”减少无效检测次数。
### 核心逻辑
- **四叉树原理**：将游戏世界递归划分为4个象限（子节点），每个节点只存储“完全包含”的物体；  
  步骤：1. 初始化四叉树，设定根节点的空间范围（如整个游戏地图）；2. 物体移动时，更新其在四叉树中的位置（从原节点移除，插入新节点）；3. 碰撞检测时，仅对“同一节点/相邻节点”的物体执行`isColliding`，而非所有物体。
- 核心优势：将碰撞检测的时间复杂度从`O(n²)`（暴力检测）降至`O(nlogn)`（分区后）。
### 应用场景
大型开放世界游戏（如100+敌人、大量道具）、弹幕游戏（成百上千颗子弹）的碰撞检测优化。
