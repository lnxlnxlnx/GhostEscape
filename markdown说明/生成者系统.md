以下从实现思路、核心修改点、关键逻辑三个维度，对每个练习方向进行简要解析，均基于原文中已有的`Spawner`类、随机数功能、特效系统等基础模块展开：


### 1. 波次生成
**核心目标**：从“固定间隔持续生成”改为“分波生成，波间有休息间隔，每波生成逻辑独立”。  
- **核心修改点**：在`Spawner`类中新增波次相关属性（如当前波次`currentWave`、波间间隔`waveInterval`、每波敌人数`enemiesPerWave`），区分“波内生成”和“波间等待”两种状态。  
- **关键逻辑**：  
  1. 新增状态变量（如`isWaveWaiting`），初始为`true`（第一波前先等待）；  
  2. `update`方法中，若处于“波间等待”，计时器累加至`waveInterval`后，切换到“波内生成”状态，重置计时器并增加波次；  
  3. 若处于“波内生成”，按`enemiesPerWave`批量生成敌人（可复用原文随机位置逻辑），生成完后切换回“波间等待”。  
  *示例*：可让`enemiesPerWave`随波次递增（如每波+5），提升难度梯度。


### 2. 条件触发生成
**核心目标**：敌人生成不再依赖固定计时器，而是由玩家行为（如接近特定区域）触发。  
- **核心修改点**：在`Spawner`中新增“触发区域”属性（如`triggerArea`，用`glm::vec2`存储区域范围），移除/弱化原计时器逻辑，新增“触发检测”逻辑。  
- **关键逻辑**：  
  1. 初始化时给`Spawner`设置触发区域（如`setTriggerArea(glm::vec2(100,100), glm::vec2(300,300))`，代表地图上的矩形区域）；  
  2. `update`方法中，实时获取玩家位置（`target_->getPosition()`），判断是否进入`triggerArea`；  
  3. 若进入且未触发过（新增`isTriggered`标记），生成敌人并将`isTriggered`设为`true`（避免重复触发，或可加“冷却时间”重置标记）。  
  *延伸*：可支持多触发区域（用`std::vector`存储），满足复杂场景需求。


### 3. 多生成点
**核心目标**：敌人不再从“摄像机范围内随机位置”生成，而是从预设的多个固定生成点中选择，提升场景策略性。  
- **核心修改点**：在`Spawner`中新增“生成点列表”（如`std::vector<glm::vec2> spawnPoints`），修改敌人位置生成逻辑，从“随机范围”改为“随机选生成点”。  
- **关键逻辑**：  
  1. 提供添加生成点的接口（如`addSpawnPoint(glm::vec2 point)`），在场景初始化时调用（如`spawner_->addSpawnPoint(glm::vec2(50,50));`）；  
  2. 生成敌人时，若`spawnPoints`非空，用游戏随机数（`game_.randomInt(0, spawnPoints.size()-1)`）选一个生成点；  
  3. 若生成点需“禁用/启用”（如某些点被玩家破坏后不生成），可给生成点加状态（如`struct SpawnPoint { glm::vec2 pos; bool isActive; }`），生成时过滤非活跃点。


### 4. Boss生成
**核心目标**：实现特殊的“Boss敌人”生成，区别于普通敌人（如更大体积、特殊属性、专属特效），且仅在特定条件（如波次达标、玩家血量达标）下触发。  
- **核心修改点**：新增`BossEnemy`类（继承`Enemy`，重写属性/行为），在`Spawner`中新增Boss生成条件（如`minWaveForBoss`、`maxPlayerHpForBoss`）和Boss状态（如`hasSpawnedBoss`）。  
- **关键逻辑**：  
  1. 定义`BossEnemy`：扩展普通敌人属性（如`maxHp`翻倍、`damage`提升），可重写`init()`方法加载Boss专属模型/贴图；  
  2. 在`Spawner`中设置Boss生成条件（如`setBossTriggerCondition(5, 50)`，代表“第5波后且玩家血量≤50%时触发”）；  
  3. `update`方法中，实时检测条件是否满足，若满足且未生成过Boss，调用`BossEnemy`的工厂方法（类似`Enemy::addEnemyChild`）生成Boss，同时设置专属生成特效（如更大范围的爆炸特效）。  
  *注意*：Boss生成后通常需禁用普通敌人生成，或调整生成频率，避免玩家压力过大。


### 5. 生成特效变化
**核心目标**：不同类型敌人（如普通敌人、精英敌人、Boss）生成时，显示不同特效（如普通敌人用“微光”，Boss用“全屏闪光”），强化视觉区分度。  
- **核心修改点**：给`Enemy`类新增“敌人类型”属性（如`enum EnemyType { NORMAL, ELITE, BOSS } type_`），在`Spawner`生成敌人时指定类型，并根据类型选择对应特效资源路径。  
- **关键逻辑**：  
  1. 扩展`Enemy::addEnemyChild`方法，新增`EnemyType`参数（如`static Enemy* addEnemyChild(Object* parent, glm::vec2 pos, Player* target, EnemyType type)`），在创建时给敌人设置类型；  
  2. 定义“类型-特效路径”映射（如`std::unordered_map<EnemyType, std::string> effectMap = {{NORMAL, "assets/effect/normal_spawn.png"}, {BOSS, "assets/effect/boss_spawn.png"}}`）；  
  3. 生成敌人时，根据当前生成的`EnemyType`，从`effectMap`中获取对应特效路径，传入`Effect::addEffectChild`方法（替换原文固定的“184_3.png”），实现特效随类型变化。
